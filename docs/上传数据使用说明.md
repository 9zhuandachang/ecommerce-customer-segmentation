# 上传客户数据并查看四项分析

## 1. 打开页面

在PowerShell运行：

```powershell
cd 'D:\桌面\AIS课件与workshop\pre2\main'
python -m streamlit run app/dashboard.py
```

打开 **http://localhost:8501**，默认进入“数据导入”页，也可随时点击侧栏“数据导入”返回。只需上传一份购买明细CSV，客户快照由系统自动生成；尚未生成分析时，四项分析入口暂不可用。

## 2. 使用真实12月演示文件

文件位于 `data/demo/2011-12-01/`，也可以点击首页“下载12月真实演示文件”后解压。

1. 在“购买明细 CSV”上传 `purchase_history.csv`。
2. 在“分析日期”选择 **2011-12-01**。
3. 点击“生成分析”，完成后自动进入“客户分群”。
4. 依次打开四个菜单，筛选客户并导出当前名单。
5. 打开“画像与商品推荐”，选择客户 **12347**，查看其购买习惯和10件推荐商品。
6. 点击侧栏“数据导入”或页面“更换数据”，可以上传另一批客户或修改日期；输入有误时保留当前分析，可点“返回当前分析”，也可从侧栏直接返回分析页。

演示日期为 **2011-12-01**，系统会自动生成 **3,444位客户**的快照；明细包含 **759,615条真实合格商品交易**，时间为2009-12-01至2011-11-30 17:37。没有合成客户、合成交易或未来标签。12月后续30天不完整，页面不展示这批预测的准确率。ZIP只包含购买明细CSV和来源记录，不要求上传快照。

## 3. 自己准备文件

购买明细CSV采用UTF-8编码，编号按文本保存，文件不超过150 MB。字段名与模板一致，不附加训练标签、未来金额、模型评分或排名。

购买明细共8列：

| 字段 | 内容 |
| --- | --- |
| `customer_id` | 客户编号，同一客户的多条购买明细可重复出现。 |
| `invoice` | 发票编号，一张发票可包含多种商品。 |
| `invoice_date` | 购买日期和时间。 |
| `stock_code` | 商品编号。 |
| `description` | 商品名称。 |
| `quantity` | 商品数量。 |
| `unit_price` | 商品单价，单位英镑。 |
| `line_amount` | 此商品行的金额，数量乘单价并保留两位小数。 |

只上传清洗后的正向商品交易，不能包含取消订单、非商品条目或完全重复行。日期和金额无效时，页面会给出具体提示。

明细应覆盖截至分析日的**完整可见购买历史**。部分特征使用近180天，更早的明细用于首次购买和累计消费特征；新客户的可见历史可以不足180天。系统自动汇总基础快照及各模型需要的其他历史特征。用户不需要计算或上传快照，但需自行确认购买历史是否完整。

分析日期可选择 **2011-09-01至2011-12-01之间任意一天（含首尾）**，不局限于月初；前端日历和后端都限制此范围。系统只使用该日期零点之前的交易，自动为此前180天至少买过一次的客户各生成一行快照；更久未购买的客户不会纳入本批分析。上传文件若包含分析日当天及之后的记录，系统会自动排除并显示排除数量。例如选2011-11-15，只使用11月15日之前的购买，预测该日起未来30天；选2011-11-01，则生成3,188位客户的快照。

## 4. 四个页面如何产生结果

| 页面 | 上传后执行的计算 |
| --- | --- |
| 客户分群 | 已保存的K-means分配群体，按群1至群4展示。 |
| 复购优先名单 | 从明细补齐购买节奏，XGBoost重新评分，再按分数排序。 |
| 高消费潜力 | 从明细补齐分时段金额，两步LightGBM重新计算消费潜力并排名；前20%按本批上传客户计算。 |
| 画像与商品推荐 | 从明细计算购买习惯、商品购买记录及EASE关联，组成D完整组34项特征；保存好的LightGBM分类模型对完整候选商品库逐件打分，取分数最高的10件。 |

模型和商品编号体系仍来自同一家UCI零售商；目前只支持2011-09-01至2011-12-01的日期，避免使用模型准备完成前的日期或超出演示数据覆盖范围的日期。陌生商品编号不会自动对应到已有商品，页面会提示当前商品库的覆盖范围。上传客户ID不作为模型特征，也不用于检索旧评分。

商品推荐现已默认采用 **D完整组＋LightGBM分类**。若页面保留的是旧规则生成的分析，会提示重新上传明细并生成；成功后四个页面恢复可用，推荐名单使用新模型。

日期扩展为推理功能：窗口仍为此前180天和此后30天，原月初训练与评估记录保持不变。程序支持任意日期，不等于已有实验证明每一天的预测精度相同。

复购评分用于排序，未经新版概率校准；消费潜力名次不代表可信的金额预测；商品库没有实时库存。页面只做推理，不用上传数据重新训练模型。

## 5. 重建和验证

```powershell
python -X utf8 -B -m app.prepare_upload_demo
python -X utf8 -B -m unittest discover -s tests
```

演示文件的来源哈希、行数和截止日期保存在同目录 `manifest.json` 中。原训练、验证、测试快照和各阶段冻结实验文件保持独立。
