报告按老师要求分为四部分，依次回答：**用了什么 → 系统怎样工作 → 效果如何 → 从结果中学到了什么。** 项目背景和四个目标放在第一部分开头，不另加一章。

下列篇幅比例仅供参考：使用的工具与技术15%，系统设计与模型35%，系统效果与评价30%，发现与讨论20%。

## 1. Tools/techniques you have used｜使用的工具与技术

这一部分交代实现项目需要哪些工具，以及分别用来解决什么问题。

### 1.1 项目背景与目标

简述电商客户分析的需求，引出四个目标：

- 客户分群：理解不同客户的购买特点。
- 未来30天复购预测：识别复购倾向较高的客户。
- 消费潜力排序：形成值得优先查看的客户名单。
- 购买习惯画像与商品推荐：理解客户的补货与尝新习惯，推荐下一单可能购买的商品。

### 1.2 技术栈及用途

## 2. System design / Models｜系统设计与模型

这一部分是报告主线，要让读者顺着数据流理解整个系统。

### 2.1 总体架构与工作流程

用流程图区分两条路径：

- **离线训练：** 交易清洗 → 构建样本 → 模型比较 → 保存最终模型。
- **实际使用：** 上传交易明细 → 选择分析日期 → 自动计算特征 → 调用模型 → 展示和导出四项结果。

### 2.2 数据与样本设计

介绍UCI Online Retail II的数据来源、时间范围、字段和规模，说明清洗后的交易如何形成客户月快照。

再说明三类数据单位，以及各自的输入和标签：

- **商品交易行：** 一张发票中的一种商品明细。
- **客户快照：** 某客户在某分析日的购买状态，用于客户分群、复购预测和消费潜力排序。
- **客户＋商品样本：** 某客户与某件候选商品的组合，用于商品级打分。

### 2.3 四个模块的模型设计

| 模块 | 需要写清楚的内容 |
| --- | --- |
| 客户分群 | 使用哪些购买特征；为什么比较K-means、二分K-means和GMM；为什么比较2—6群；最终K-means四群分别有什么特点。 |
| 复购预测 | 标签如何定义；8、11、14项特征组的区别；为什么比较LR、样条LR、XGBoost和LightGBM；最终XGBoost评分怎样产生。 |
| 消费潜力排序 | 20项历史特征；金额规则、直接金额模型与两步模型的区别；解释“购买倾向 × 购买后的条件金额”如何形成排序分数。 |
| 画像与商品推荐 | 10项购买习惯画像如何形成；先比较五种推荐方法，再比较A—D四组特征×三类模型；解释当前D组34项特征如何为“客户＋商品”打分并生成Top10。 |

### 3.2 评价指标及计算方法

| 模块 | 重点指标 |
| --- | --- |

四个模块分别呈现比较表和逐月结果。
