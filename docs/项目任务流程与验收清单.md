# 电商客户分群与 30 天复购预测：任务流程与验收清单

> 本清单记录早期八阶段方案及其当时的验收状态。当前课程演示已改用 K-means 四群与 14 项特征的 XGBoost 统一历史回放；新流程和回顾性结果见 [项目学习指南](项目学习指南.md)及 [统一回放报告](../stage6/outputs/reanalysis_v2/report.md)。以下旧三群、RFM、SoftVote 和“独立测试”表述只用于理解早期实验，不代表当前页面。

> 当前扩展功能还包括[两步LightGBM消费潜力排序](../value_prediction/outputs/ranking_comparison_v1/report.md)和[下一笔订单商品推荐](../recommendation/outputs/v1/report.md)。推荐第一轮比较三种算法和两种规则，个人重复购买胜出并成为后续对照；下文“不做商品推荐”属于早期MVP范围记录。

> 推荐目标随后结合[购买习惯画像与四组推荐比较](../recommendation/outputs/profile_v2/report.md)：画像混合的验证提升很小，该轮保留个人重复购买。该轮记录见[画像推荐案例](../recommendation/profile_demo.md)，不代表当前默认推荐。

> 最新一轮为[四组特征×三类模型的商品级打分](../recommendation/outputs/item_v3_1/report.md)，[打开与案例](../recommendation/item_demo.md)。当前项目已将 **D完整组＋LightGBM分类** 设为默认推荐，验证NDCG0.3448、Recall21.21%，9—11月复核NDCG0.3001、Recall17.79%。上传明细后重新计算34项特征并生成Top10；前端保留数据导入和四项分析，不提供算法切换。原实验选择记录保留，其他三个目标未改动。

## 项目目标与执行顺序

面向**有可识别购买记录的现有客户**，用历史交易建立客户分群，并预测其在未来 30 天内再次购买的可能性。最终交付可运行的 Streamlit 仪表板，支持查看群体、按模型评分排序和导出人工审核名单。

按以下顺序推进；每阶段通过验收后，再以其产物开展下一阶段：

**1. 明确口径与范围 → 2. 数据清洗与审计 → 3. 客户快照与标签 → 4. 分群与参考基线 → 5. 六组预测实验 → 6. 评估与模型定稿 → 7. 仪表板集成 → 8. 测试与最终交付。**

项目提案位于上一级 `pre2` 目录。本目录已有两份原始 CSV、数据清洗与快照脚本、对应输出和单元测试；分群、建模及仪表板原型现已接入客户快照，并生成本地训练产物，但实验设计与本清单仍需对齐，也尚无最终评估报告。下面的复选框均表示待逐项核验，不把“已有文件”直接等同于“已验收”。

## 阶段 1：明确业务范围和统一口径

**任务细则**

1. 确定使用者为客户关系管理或客户留存团队；核心问题是“客户购买行为有何差异”和“哪些现有客户更可能在未来 30 天复购”。
2. 固定研究对象：UCI Online Retail II 的两份年度交易 CSV。交易明细行不是独立客户；客户 ID 用于关联和导出，不作为预测特征。
3. 统一“合格购买”“现有客户”“客户快照”“模型评分”的含义，并记录不适用情形。评分在完成校准检查前，不直接称为真实复购概率。
4. 固定 MVP 边界：支持历史截止日期选择、群体查看、筛选、Top N 排序和 CSV 导出；不做营销发送、商品推荐、实时系统接入、新客户评分、仪表板内训练或营销增量效果推断。

**阶段产物**：[业务范围与数据口径](业务范围与数据口径.md)。PPT 和中文提案是 2026 年 9 月的计划版本；当前实现状态和计划差异在该文档及 README 中逐项说明。

**验收清单**

- [x] PPT、中文提案、代码与后续界面对目标、数据范围和输出字段的说法一致；计划与当前原型进度已区分。
- [x] 明确交易行、发票、客户和客户快照四种统计单位，购买频次按不同的合格发票计数。
- [x] 所有超出 MVP 的功能和不能由数据支持的结论均已写明。

## 阶段 2：数据清洗与审计

**任务细则**

1. 读取两份原始 CSV，统一字段名和类型，保留来源文件及原始行号；原始文件保持不变。
2. 去除完全重复行；排除缺失客户 ID、无效日期或关键字段、取消订单、数量或价格非正、非商品类编码等记录。每条排除记录保留一个主要原因，并统计各规则命中数。
3. 核对清洗前后记录数，说明缺失客户 ID 等规则对可建模数据覆盖范围的影响；保留规则清单，便于复现。

**阶段产物**：`clean_transactions.csv`、`excluded_transactions.csv`、`cleaning_audit.csv`，以及清洗规则说明。现有 `build_customer_snapshots.py` 和 `data/processed/customer_snapshot_pipeline/` 已提供这些产物。

**验收清单**

- [ ] 原始行数 = 合格交易行数 + 排除行数；审计表的主要原因计数与原始行数对齐。
- [ ] 合格交易无完全重复行、无缺失客户 ID，且数量和单价均为正。
- [ ] 能从任一排除记录追溯来源文件、原始行号和主要排除原因。
- [ ] 清洗规则、排除规模及其对客户覆盖范围的影响已记录。

## 阶段 3：客户快照、特征与复购标签

**任务细则**

1. 每月 1 日设一个截止时间 `t`。仅为此前 180 天内至少有一次合格购买的客户生成快照。
2. 仅用 `[t−180 天, t)` 内的交易构建最近购买间隔、合格发票频次、消费金额、平均订单金额、商品多样性、近 30/90 天购买次数等特征；需要更早历史的指标应明确其来源和含义。
3. 用 `[t, t+30 天)` 内是否至少有一次合格购买生成二元标签。排除未来 30 天观察期不完整的截止日期。
4. 按时间先后划分训练、验证、测试；若较早分区的标签窗口跨越下一分区起点，则将相应快照排除出建模。保留日期边界和分区表。

**阶段产物**：`cutoff_schedule.csv`、`customer_snapshots.csv`、`validation_report.csv`、`run_manifest.json`。现有流水线已生成上述文件。

**验收清单**

- [ ] 每个“截止日期 + 客户 ID”组合唯一，客户在观察窗口内有至少一次合格购买。
- [ ] 截止时间及之后的交易不进入该日特征；标签仅取未来 30 天合格购买，且只含 0/1。
- [ ] 所有标签窗口完整；训练、验证和测试按时间顺序排列，跨边界标签不参与建模。
- [ ] 能用源文件、配置和脚本重建相同口径的快照，并保留来源哈希与运行记录。

## 阶段 4：客户分群与参考基线

**任务细则**

1. 在训练数据上确定偏态特征变换、缺失值填补和缩放方法，并拟合 K-means；比较 `k = 3、4、5、6`。
2. 同时看轮廓系数、各群体规模和群体画像。画像至少包含客户数、最近购买间隔、发票频次和消费金额；在看过画像后再给群体命名。
3. 计算客户到各已拟合聚类中心的距离，供后续预测实验使用。另建立最近购买时间排序和 RFM 排序，作为简单参考基线。

**阶段产物**：`stage4/kmeans.py`、`stage4/stability.py`、`stage4/outputs/stage4/` 下的分群流水线、各 `k` 比较、群体画像、中心距离、参考基线、运行报告和三群/四群稳定性检查。默认读取仓库内客户快照；依赖版本见根目录 `requirements.txt` 与阶段四运行记录。

**验收清单**

- [x] 填补、变换、缩放和 K-means 只在相应训练部分拟合；验证集、测试集只应用已拟合步骤。
- [x] `k = 3–6` 的选择有指标、群体规模及可解释性依据；没有把任意群体名称当作预先给定事实。
- [x] 聚类中心距离可由保存的聚类模型稳定重算；参考基线使用相同的合格样本与时间划分。

## 阶段 5：完成六组预测实验

**任务细则**

1. 准备两组特征：A 为基础交易特征；B 为基础特征加聚类中心距离。两组都不包含客户 ID、标签或截止时间之后的信息。
2. 每组分别训练逻辑回归（LR）、梯度提升决策树（GBDT）和两者的软投票模型，共六组实验。六组使用相同的快照、标签和时间划分。
3. 软投票按 `w × p(LR) + (1−w) × p(GBDT)` 计算；在各自特征组的验证数据上，从 `w = 0.25、0.50、0.75` 中选择权重。
4. 如采用滚动验证，每一折都重新拟合该折训练部分的填补、缩放、聚类和分类模型。记录配置、随机种子、版本和结果，保证实验可复现。

**阶段产物**：`stage5/experiments.py` 和 `stage5/outputs/stage5/` 下的可复现训练代码、配置、验证集预测与结果表。

**验收清单**

- [x] 六组实验均可运行，且对比只改变规定的特征组和模型类型。
- [x] 所有预处理、聚类和分类器仅用对应训练数据拟合；测试集未参与调参或权重选择。
- [x] 软投票权重按验证集结果确定，计算方式和最终选值可查。
- [x] 能与简单排序基线比较，并如实记录“加聚类距离”或“软投票”没有改善的情况。

### 阶段五增强实验：验收标准

原六组实验保留为对照；增强实验的代码和结果位于 `stage5/extended.py` 与 `stage5/outputs/extended/`。

- [x] 新增 C 组仅使用快照日之前可见的 4 项购买节奏特征；A/B/C 各运行 LR、GBDT、软投票，共九组，并使用相同的官方训练、验证划分。
- [x] 在训练期内部对 2011 年 3、4、5 月做三轮滚动验证；每折训练标签的 30 天窗口都在验证月开始前结束，B 组的聚类与所有填补、缩放、分类步骤逐折重拟合。
- [x] LightGBM 只比较 15/31 个叶子、最多 500 棵树；每折在训练部分内部留一个月监控 AP 并早停，外层验证月只用于参数比较。树数、叶子数及软投票权重的选值与候选结果可追溯。
- [x] 九组模型、RFM 基线、逐月指标、逐条验证评分及来源哈希均已导出；官方验证期只在配置选定后评估，测试期未参与调参或本轮指标计算，负向特征实验结果如实记录。

## 阶段 6：评估、选择并保存模型

**任务细则**

1. 以验证集平均精确率（AP）选模型，同时报告 ROC-AUC、Precision、Recall、F1。对于 Top 20% 名单，报告 Lift、Precision@20% 和 Recall@20%。
2. 查看混淆矩阵、类别占比、概率校准、按时段及群体拆分的表现；适用时计算 Brier 分数。分类阈值如需使用，应在最终测试前确定。
3. 固定模型与配置后，只对留出的较晚测试时段做最终评估；区分验证结果、测试结果与普通历史视图结果。
4. 保存预处理步骤、已拟合 K-means、选定分类器及配置和模型版本。若简单模型更好，可以选择它，并保留六组实验记录。

**阶段产物**：模型比较与讨论报告、最终测试结果、可加载的模型流水线和版本记录。

**验收清单**

- [x] 模型按官方验证 AP 选定；仅保留 RFM 基线在相同测试期报告；Top 20% 每月分别取名额，测试时段为 2011 年 9–11 月；未预设准确率或收入提升结论。
- [x] 测试期分箱仍显示一定低估；阶段六报告称“模型评分”，旧仪表板明确标为原型评分，不解释为营销增量效果。
- [x] 测试结果在模型、校准及 F1 阈值写入带哈希的冻结配置后生成；Top 20% 名单按每月固定 20% 名额计算。
- [x] 已保存预处理、训练期 K-means、分类器、校准器和版本；重新加载后在同一测试输入上复现分群和评分。

## 阶段 7：集成 Streamlit 仪表板

**任务细则**

1. 用户只上传购买明细，可选2011-09-01至2011-12-01之间任意一天；前后端限制范围，系统自动排除当天及之后的交易并生成客户快照，再加载冻结模型重新分群、评分与排名，不读取预存客户结果。
2. 只提供客户分群、复购优先名单、高消费潜力、画像与商品推荐四个业务入口，支持筛选和CSV导出。
3. 页面及导出显示分析日期和有用业务字段，不展示模型版本、实验对比或未来答案；输入错误和空筛选结果有明确提示。

**阶段产物**：可运行的 Streamlit 原型及其启动说明。

**验收清单**

- [x] 从上传到四页分析、筛选及导出有应用测试；真实12月文件含3,444位客户，不含未来标签。
- [x] 导出与当前可见业务名单一致；新推理入口复现原11月的分群、复购分数、消费潜力名次和客户12347商品推荐。
- [x] 日期由用户选择，快照由明细自动汇总；系统拒绝缺失字段、重复明细、非数值及矛盾金额，自动排除分析日或之后的交易，确保不进入四项分析。
- [x] 模型不在界面重训；12月只提供预测，不报告缺少完整答案的准确率。原各阶段实验及模型文件保留。
