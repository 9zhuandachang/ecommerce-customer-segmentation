# 金额模型统一验收复核规则

本文件仅把 `optimization_protocol.md` 已有的强化目标写成统一计算规则，不增加模型、改变阈值或将已查看数据重新定义为独立测试。先记录规则，再生成统一对照表。

## 同一批客户、同一份未来标签

每个评估月份内，对照 `historic_180d` 与固定 `extended_tweedie` 的快照数、未来购买者数、实际总金额及 Top20 名额必须相同；每个方法每月最多一行。跨月汇总用客户月行数加权 MAE、购买者行数加权购买者 MAE，并按真实总金额汇总 Top20 覆盖和金额偏差。已有报告中的派生覆盖率和总额偏差要与基础金额重新计算后吻合。不完整或不一致的记录不得给出通过结论。

## 原强化目标

与同批客户历史金额基线比较，固定要求：整体 MAE 至少降低 10%；实际购买者 MAE 至少降低 5%；每月选预测金额前 20% 客户、合并实际消费覆盖至少增加 3 个百分点；全体预测总额偏差在 ±5%；Top20 名单的预测总额偏差在 ±10%；至少三个按时间向前的月份中，模型月度 MAE 和 Top20 覆盖同时不差于基线。Top20 群体偏差若未保存，记为“证据缺失”，不可默认通过。缺少三个月或任一必要字段也不能通过。

## 来源与结论边界

在已有输出上仅复核固定的原商家 2011 年 1–5 月、6–8 月、9–11 月以及四个已做过的跨商家结果；其来源状态分别为开发、已查看确认、已查看回顾和其他商家。上述来源状态都**不满足原商家未来新月份的独立验收**。即使某组计算指标全部达标，也只说明其历史技术门槛；正式接入还必须有未用于选择、训练或查看结果的同商家新月份，且来源和标签经过独立审计。此审计不能只凭调用者提供一个 `independent=True` 就给当前数据放行。
